# MatrixCode passive news document architecture

## Security invariant

**MatrixCode never interprets executable web content.**

The screensaver renderer accepts only normalized, passive document data
generated by a separate ingestion process.

HTML, JavaScript, CSS, WebAssembly, SVG scripting, browser plugins, iframes,
forms, event handlers, remote fonts and other active web technologies are never
processed by the MatrixCode screensaver runtime.

This is an architectural invariant, not merely an importer preference.

## Trust boundary

The long-term pipeline is:

```text
Internet
   |
   v
network-enabled collector
   |
   | fetches untrusted pages
   | does not require the screensaver to execute page code
   v
sanitizer / extractor
   |
   | removes active content
   | extracts article semantics
   | normalizes passive layout intent
   | downloads and re-encodes allowed images
   v
neo_news_article
   |
   v
neo_document
   |
   v
PageMaker-inspired layout engine
   |
   v
MatrixCode renderer
```

The MatrixCode renderer must be able to operate with network access disabled.

## `neo_news_article`

`neo_news_article` is the provider-facing news model.  It represents article
identity and semantics: title, summary, body segments, language, provider,
timestamps and provenance.

Current backend:

```text
matrix1999-film-corpus
```

Possible future backends:

```text
RSS
Atom
news APIs
local archive
SQLite cache
sanitized HTML extraction
```

Providers must normalize their data before it reaches the renderer.

## `neo_document`

`neo_document` is the safe intermediate representation between news data and
visual layout.

It contains only passive primitives such as:

- heading
- lead
- paragraph
- byline
- dateline
- image reference
- caption
- quote
- list
- table
- divider
- metadata

It may contain harmless style roles such as headline/body/caption, alignment,
bold and italic.

It may also contain optional normalized source-layout hints (`x`, `y`, `width`,
`height` in the range 0..1).  These preserve broad layout intent from a source
page without preserving CSS or requiring a browser engine.

## What `neo_document` cannot contain

There is intentionally no representation for:

```text
JavaScript
WebAssembly
CSS rules
event handlers
DOM callbacks
iframes
forms
browser plugins
remote fonts
inline executable SVG
arbitrary browser objects
```

If the passive document type cannot express something, the renderer cannot
accidentally execute it.

## URLs are metadata only

A source URL can be retained for provenance and future UI display, but it is
inert metadata.

The renderer must never dereference a URL stored in a document.

Fetching belongs exclusively to the collector side of the trust boundary.

## Images and other assets

Future web ingestion should decode untrusted media outside the screensaver
runtime, strip metadata, enforce strict dimensions and resource limits, and
re-encode it into a small set of local passive formats.

A recommended policy is:

```text
JPEG / PNG / WebP / SVG / other source media
                    |
                    v
              sandboxed decoder
                    |
                    v
               raw pixels
                    |
          strip metadata / resize
                    |
                    v
             re-encode to PNG
                    |
                    v
           content-addressed asset
```

SVG should be rasterized.  MatrixCode should not interpret SVG markup.

`neo_document_block.asset_id` identifies an already-sanitized local asset.  It
is not a network URL.

## Original HTML

Raw downloaded HTML does not belong in the renderer's normal cache.

The safest default future policy is:

```text
fetch -> extract -> normalize -> discard original HTML
```

An optional collector/debug mode may retain original pages in a quarantine
area for later reprocessing.  MatrixCode itself must never read from that
quarantine area.

## Rendering and source layout

The goal is not to reproduce arbitrary websites as browsers do.

The ingestion layer extracts:

```text
content semantics
+
safe source-layout hints
```

The PageMaker-inspired MatrixCode layout engine then decides how to present the
document in the fictional 1999 workstation style.

For example:

```text
source website
  headline across top
  hero image right
  article body below

          becomes

MatrixCode document
  headline frame
  metadata rail
  linked text columns
  image frame
  scrolling pasteboard/document viewport
```

The source influences composition, but never controls executable presentation.

## Runtime separation

A future deployment should prefer separate processes:

```text
matrixcode-newsd
  network allowed
  writable cache
  untrusted-input parsers

matrixcode
  no network required
  read-only normalized documents
  read-only sanitized asset cache
```

Additional OS sandboxing can strengthen this boundary later.

## Current implementation status

The project currently has:

```text
data/neo-workstation/search-results.json
        |
        v
tools/generate-neo-news.py
        |
        v
neo_news_article
        |
        v
neo_document
        |
        v
Neo workstation renderer
```

No web importer exists yet.

That is intentional.  The renderer and intermediate representation are being
designed first so a future importer has a narrow, explicit and safe target
format.
